# Contract: HTTP API convention and endpoints (RM-1)

Applies to every endpoint in every slice (API-001, DEC-002, FR-011 to FR-013, FR-019). Shapes are defined in [data-model.md](../data-model.md).

## Convention

- Paths: under `/api/`, resource-style, plural nouns, readable IDs: `/api/issues/WEB-42`, `/api/projects/WEB/labels`. Keys and IDs are matched ignoring capitals (API-004).
- Bodies: JSON in and out (`Content-Type: application/json`). Times are ISO 8601 strings in UTC.
- Methods: `GET` read, `POST` create, `PATCH` update, `DELETE` delete.
- Every route handler is wrapped by the shared `apiRoute` wrapper, which provides the error shape, the `500` guard and the request log line.
- Tokens never go in path segments: the logger drops the whole query string but logs the path, and AGENTS.md states this rule (SEC-007).

## Errors

| Status | When | Body |
|--------|------|------|
| `401` | Not signed in (STD-1; from RM-3) | `{ "error": { "message": "…" } }` |
| `403` | Not allowed (STD-2; from RM-3) | `{ "error": { "message": "You don't have permission to do that." } }` |
| `404` | Unknown `/api/…` path, or item not found (STD-4) | `{ "error": { "message": "Not found" } }` |
| `422` | Invalid input (STD-3) | `{ "error": { "message": "…", "fields": { "name": "Enter a name." } } }` |
| `500` | Any unexpected failure | `{ "error": { "message": "Something went wrong." } }`; no stack or internal detail |

Handlers raise `401`/`403`/`404`/`422` by throwing `ApiError(status, message, fields?)`.

## Request ID on creates (FR-013, DEC-002)

Every create (`POST`) body carries `"requestId": "<UUID v4 generated by the browser>"`. The server stores it with the created row under a unique constraint and, on a repeat with the same `requestId`, answers with the row already created instead of creating a second one. RM-1 defines this convention only; the first slices with create endpoints implement it.

## Endpoints in RM-1

### `GET /health` (not under `/api`, no sign-in)

| Case | Status | Body |
|------|--------|------|
| Database answers `select 1` within 800 ms | `200` | `{ "status": "ok" }` |
| Database fails or does not answer in time | `503` | `{ "status": "unavailable" }` |

Never cached. Logged like any API request.

### `ANY /api`, `/api/` and `/api/{anything}` with no matching route

Also bare `/api` and `/api/`. `404` with the error shape above, never an HTML page. The route is the optional catch-all `src/app/api/[[...path]]/route.ts`. Specific routes added by later slices take precedence over this catch-all. The catch-all exports `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD` and `OPTIONS`, each through `apiRoute`: every one answers an unknown path with the JSON `404` and writes one timing log line.
