# AGENTS.md

## Commands

Build, test and lint with the scripts in `package.json`; run them from the repository root. Setup steps (Node.js, PostgreSQL, databases, `.env.local`) are in `README.md`.

## Sources

- `specs/`: each slice's spec, plan and tasks.

## Conventions

- Source layout: `src/app` holds routes, layouts and composition only. Shared UI goes in `src/components/ui` (vendored Hairline in `src/components/ui/hairline`, imported through its `index.ts`) and `src/components/layout`. Code for one feature goes in `src/features/<feature>/` (`components/`, `hooks/`, `services/`). Shared hooks go in `src/hooks`, shared browser utilities in `src/lib`, server-only code in `src/server`, shared types in `src/types`, global CSS in `src/styles` and static files in `public/`. Tests sit beside the code they test. Imports are relative and keep the `.ts`/`.tsx` extension (there is no `@/` alias).
- Schema changes are new SQL files in `migrations/` (create the folder with the first one), applied in name order by `npm run db:migrate`. Each must keep working with the previous release's code (OPS-004). Once applied, a migration file is never edited, renamed or deleted.
- Every timestamp column is `timestamptz`, and values are written in UTC (DATA-003).
- Every route handler lives under `src/app/api/…/route.ts` (the one exception is `GET /health` in `src/app/health/route.ts`), uses resource-style plural paths (`/api/projects/WEB/labels`) and JSON bodies, and is wrapped in `apiRoute` from `src/server/api.ts`. Before the handler runs, `apiRoute` itself answers `403` "You don't have permission to do that." to a cross-site `POST`, `PUT`, `PATCH` or `DELETE` (FR-018). The handler raises `401`, `403`, `404` and `422` by throwing `ApiError`, and `429` and `503` too when requesting a sign-in link (DEC-002); the wrapper turns anything else into a `500`. Unmatched `/api` paths fall through to the catch-all `src/app/api/[[...path]]/route.ts`, which answers a JSON `401` when signed out and `404` when signed in (`specs/001-project-foundation/contracts/http-api.md`).
- Every `src/app/api/…/route.ts` exports each HTTP method Next supports for route handlers (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS`); the ones it doesn't implement are `unmatchedRoute` from `src/server/permissions.ts`, so Next never answers a bare `405` or its own `OPTIONS` or `HEAD` outside `apiRoute`.
- Pages are protected by `src/proxy.ts`. Every `/api` handler except the three sign-in endpoints (`POST /api/sign-in-links`, `POST /api/sessions`, `DELETE /api/sessions/current`) calls `requireMember` from `src/server/permissions.ts`.
- Every create (`POST`) body carries a `requestId` generated by the browser with `crypto.randomUUID()`. The server stores it with the created row under a unique constraint and answers a repeat with the row already created (specs/001-project-foundation FR-013). Sign-in-link `requestId`s are kept in their own table (`sign_in_requests`) rather than on a created row, and a non-member's request has no row of its own; `POST /api/sessions` replays only when the token matches.
- Tokens never go in path segments, because the request path is logged (SEC-007).
- Secrets live only in the git-ignored `.env.local`, never in the repository (OPS-006). The committed `.env.example` holds placeholders only.
